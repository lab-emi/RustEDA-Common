# The `rusteda` command-line program (`crates/apps/rusteda-cli`)

## Global interface

**RCLI-REQ-0001** The `rusteda` binary provides generic workspace commands (`init`, `import`, `log`, `show`, `diff`, `revert`, `export`, `completions`) with no tool-specific engine or checker dependencies. It also provides the planning commands of the Ibex recipe's native frontend (`estimate-spef`, `eco-round`, `frontend-profiles`, `frontend-physical`, `frontend-pins`, `frontend-validate`; RCLI-REQ-0026 to RCLI-REQ-0028), which write their reference helpers' files instead of workspace revisions.

**RCLI-REQ-0002** Global options `-w`/`--workspace <DIR>` (required for every subcommand except `completions`), `--format text|json`, `--threads <N>`, `-q`/`--quiet`, `-v`/`--verbose`, `--color auto|always|never`, and `--progress auto|always|never` are accepted before or after the subcommand name; `-V`/`--version` prints `rusteda <version>`.

**RCLI-REQ-0003** Standard input is never read by any `rusteda` command; commands succeed or fail deterministically when spawned with a closed or null standard input stream.

**RCLI-REQ-0004** In `--format json` mode, every invocation prints exactly one `rusteda.v1` envelope on standard output (with keys in contract order and all standard keys present), including usage errors, `--help`, and `--version` (via pre-scanning `--format` before argument parsing).

**RCLI-REQ-0005** In `--format text` mode, mutating commands begin standard output with `rev<N>  <command>  (base rev<M>)` and end with `next: <command>` lines; diagnostics and errors are written to standard error as `<severity>[<code>]: <location>: <message>` with optional `  help: <hint>` lines.

**RCLI-REQ-0006** Every `next_actions` entry in JSON and text output is a canonical command line with words POSIX-quoted (`=`-prefixed words quoted for `zsh`).

**RCLI-REQ-0007** Exit codes follow contract §7: `0` on success, `1` on usage or input/workspace rejection (`USAGE`, `INPUT_REJECTED`, `NOT_A_WORKSPACE`, `WORKSPACE_EXISTS`, `UNKNOWN_REVISION`, `MISSING_TABLE`, `UNKNOWN_HANDLE`, `SCHEMA_TOO_NEW`, `IO_ERROR`, `BACKEND_UNAVAILABLE`), `2` on internal or corruption failures (`INTERNAL`, `CORRUPT_TABLE`), `4` on `REVISION_CONFLICT`, and `130` on `CANCELLED`.

**RCLI-REQ-0008** Every workspace-changing command (`init`, `import`, `revert`) appends a line to `history.jsonl`, including commands rejected by input validation, usage errors on an existing workspace, or `REVISION_CONFLICT`; pure queries (`log`, `show`, `diff`, `export`, `completions`) never write to `history.jsonl`.

## Workspace initialization and import

**RCLI-REQ-0010** `rusteda init -w <DIR>` initializes a new workspace at `DIR` at `rev0`, failing with `WORKSPACE_EXISTS` if `DIR` already contains a `manifest.json`.

**RCLI-REQ-0011** `rusteda import -w <WS> --base-rev <REV> [-m <TEXT>]` commits one new revision on top of `REV` carrying all tables requested in that invocation (`--lib`, `--rtl`, `--netlist`, `--sdc`), applying carry-forward invalidation to dependent tables from the base revision, and failing with `REVISION_CONFLICT` (exit 4) if `HEAD` is not `REV`.

**RCLI-REQ-0012** `rusteda import --lib <FILE> [--corner <NAME>]` is repeatable; each `--corner` applies to the preceding `--lib` (default corner `"default"`). Each library is validated with `rusteda_formats::liberty::read_text_diags`, replaying reader warnings as `L`-series envelope diagnostics and rejecting syntax or model/unit errors (`INPUT_REJECTED` with `file:line:col`). Validated libraries are stored in `cache/<name>-<h16>.lib` and `.rlib` and recorded in `meta.json` `libraries`.

**RCLI-REQ-0013** Within a revision, `(library_name, corner)` is unique, and defining the same cell name twice within one corner is rejected at import with an `L`-series error diagnostic and `INPUT_REJECTED`.

**RCLI-REQ-0025** `rusteda import --lib-cache <DIR>` shares compiled libraries between workspaces (WS-REQ-0085 to WS-REQ-0087); `DIR` is created when missing, and one that is not a directory is `IO_ERROR`. A `--lib` whose bytes this executable compiled before from the same path, as recorded in `DIR` (schema `rusteda.lib-cache-record.v2`: the xxh3-64 of the executable, of the bytes and their length, the source path, the library name, the xxh3-64 and length of the compiled `.rlib` published with it, its cell names and the reader's diagnostics, none an error), is not parsed again: the recorded diagnostics are replayed and the cell checks of RCLI-REQ-0013 run on the recorded cells, and the workspace cache gets its own copies of the `.lib` (from the bytes read) and of the shared `.rlib`, once that is exactly the recorded one. Any other library is parsed and compiled as without the option and then published to `DIR`; a record that does not match, a shared `.rlib` that is not the recorded one, and an executable that cannot be read fall back to parsing (and publishing again). The envelope, the diagnostics, the metrics, the revision and the workspace cache files are the same as without the option, and no workspace cache file is a link of a shared one; a failure to publish does not fail the import.

**RCLI-REQ-0014** `rusteda import --rtl <FILE>... --top <NAME> [-D <NAME>[=<VAL>]]... [-I <DIR>]... [-P <NAME>=<VAL>]... [--no-predefined-macros]` resolves the `` `include `` closure of the given Verilog files hermetically (searching only the including file's directory and `-I` directories, with no CWD fallback and no external absolute or parent-escaping include paths), writes the snapshot files and `rtl.json` (`{top, defines, params, files: [{path, hash}], predefined_macros}`) into the `rtl` directory table, and reports preprocessor/expression errors as `V`-series diagnostics with `file:line:col` locations.

**RCLI-REQ-0021** `rusteda import --rtl <FILE>... --top <NAME>` also takes BLIF files (`.blif`) and AIGER files (`.aag`, `.aig`), the format chosen by the extension, ignoring letter case. All files of one import have one format, and AIGER takes one file; otherwise, and when `-D`, `-I`, `-P` or `--no-predefined-macros` are given with BLIF or AIGER files, the import is a `USAGE` error. BLIF files are validated with `rusteda_formats::blif` with `--top` as the top model, and an AIGER file with `rusteda_formats::aiger`, without properties; reader errors reject the import (`INPUT_REJECTED`) with their `B`- and `G`-series diagnostics and locations, and reader warnings are kept as diagnostics. The files are stored in the `rtl` directory table as given, without include closure.

**RCLI-REQ-0022** `rtl.json` records the format of a BLIF or AIGER snapshot in `format` (`"blif"` or `"aiger"`); for SystemVerilog the field is absent, and a manifest without it is SystemVerilog, so that manifests written before the field read unchanged.

**RCLI-REQ-0019** `rusteda import --netlist <FILE>` reads a structural gate-level Verilog netlist, resolves every instantiated library cell and pin against the revision's libraries across all corners (rejecting unknown cells/pins and cross-corner pin-direction conflicts with `V`-series diagnostics and `file:line:col` locations), drops `pg_pin` connections and supply ports with one aggregated `V`-series warning, encodes the frozen netlist into `netlist.rbin` (`NETLIST` v1) with an empty upstream map, and records the source in `meta.json` `sources`.

**RCLI-REQ-0024** `rusteda import --netlist <FILE>` reads a flat netlist with a bounded streaming reader when it can. A netlist that the streaming reader declines is read with the full Verilog reader only when the file is at most `--max-netlist-ast-mib <MIB>` mebibytes (default 64); a larger one is rejected before the full reader runs (`INPUT_REJECTED`, a `V0300` error that names the budget and the option), and HEAD does not move. The budget does not apply to a netlist that the streaming reader takes, and the option requires `--netlist`. The full reader holds the whole syntax tree in memory: its peak resident memory was measured at about 42 times the file size (1.07 GiB for a 26 MiB flat netlist, against 95 MiB with the streaming reader), so the default bounds it near 2.6 GiB. Estimate the memory before raising the budget.

## Queries, revert, export, and completions

**RCLI-REQ-0015** `rusteda log -w <WS> [--limit <N>]` lists committed revisions newest-first with `rev`, `parent`, `command`, `message`, `tables`, and `created_unix_ms`.

**RCLI-REQ-0016** `rusteda show -w <WS> [--rev <REV>]` (default `HEAD`) reports the revision's metadata (`tables` with hashes and upstreams, `libraries`, `sources`, `dropped`, `summary`, `status`), rendering a missing `sta` status as `timing: "not_analyzed"` and a missing `check` status as `equivalence: "unchecked"`.

**RCLI-REQ-0017** `rusteda diff -w <WS> --from <REV> --to <REV>` reports added, removed, changed, and unchanged table hashes, library changes, numeric summary metric deltas, and status transitions between the two revisions.

**RCLI-REQ-0018** `rusteda revert -w <WS> --base-rev <REV> --to <REV>` moves `HEAD` from `--base-rev` to `--to` under the exclusive workspace lock without creating a new revision directory, logging the revert in `history.jsonl`; `rusteda completions <SHELL>` outputs completion scripts for `bash`, `elvish`, `fish`, `powershell`, and `zsh`.

**RCLI-REQ-0020** `rusteda export -w <WS> [--rev <REV>] --netlist <FILE>` (default `HEAD`) streams the revision's validated mmap `netlist` table as deterministic structural Verilog (with escaped identifiers per IEEE 1364-2005 §3.7.1), without modifying the workspace or appending to `history.jsonl`. `--kind connectivity-json` selects the [bounded native connectivity projection](connectivity.md), preserving original bus orientation and structural aliases. The receipt binds revision, table, explicit interface schema and output hashes. The default remains Verilog.

**RCLI-REQ-0026** `rusteda estimate-spef -w <DIR> --def <DEF> --lef <LEF> --policy <JSON> --base-rev empty` writes the placement-based RC estimate of the Ibex recipe's reference estimator (`integration/ibex_sg13g2_ez130/estimate_spef.py`, policy schema `rusteda.rc-estimate-policy.v1`) into a fresh directory: it takes `DIR/workspace.lock` exclusively, refuses a directory holding anything else or a base other than `empty` (`REVISION_CONFLICT`), and writes `estimate.spef`, `result.json` (`rusteda.rc-estimate-result.v1`) and `HEAD` (`rev1`) with the reference's bytes for the same inputs: the same LEF and DEF line rules, net and instance numbering, rectilinear Prim tree (lowest index among equal distances), macro detours, segment split, `%.5e`/`%.9e` SPEF numbers, shortest round-trip floats, decimal rounding and compensated sums in the report, and its JSON layout. Standard output is the reference's one-line summary rather than a `rusteda.v1` envelope; a failure writes `{"status": "failed", "error": ...}` on standard error and exits 2. Inputs that are not ASCII are rejected.

**RCLI-REQ-0027** `rusteda eco-round -w <ECO_DIR> --bundle <BUNDLE_DIR> --context <JSON> --operation reset|fanout|primary-clock|electrical|hold --timing-tag <TAG> --source <NETLIST> --graph <JSON> [--timed <NETLIST>] --base-rev empty [--plan-only]` plans and applies one ECO round of the Ibex recipe's native frontend in one process. It is the native form of the recipe's reference helpers (`integration/ibex_sg13g2_ez130/native_frontend_inputs.py bundle --eco-workspace`, which runs the planner stage of `native_ecos.py`), and writes their files byte for byte from the same inputs: key order, shortest round-trip floats, decimal rounding, compensated sums, stable sorts and the planner's work-unit count are the reference's.

- Inputs. `--context` is the run's pinned context (`rusteda.native-frontend-context.v1`: `run_root`, `files` and `tools` as `{path, sha256, bytes}` records, `selection`); every record is checked first (`pinned input changed: <name>`), with digests taken from the run's flow digest cache `<run_root>/frontend/sha256-cache.json` while a file keeps its identity (device, inode, size, mtime, ctime). `--source`, `--timed` (default: the source) and `--graph` (a `rusteda export --kind connectivity-json` graph of the source) must lie inside `run_root`. The round reads, by the reference's conventions under `run_root`: `frontend/profiles/{io,delay,sizing,cell-buses}.json`, the four pin tables `logs/fe_caps_{tt,ss}_{std,ram}.stdout`, the reports `logs/fe_<TAG>_{tt,ss}_drv.stdout` and their compiled STA workspace, `frontend/bundle-reset/roots.json` (every round but `reset`), and for `electrical` and `hold` also `logs/fe_<TAG>_{seed,def,hold}.stdout`, `logs/fe_<TAG>_{tt,ss}_endpoints.stdout`, `frontend/estimate-<TAG>/{estimate.spef,result.json}` and (`hold`) `frontend/eco-electrical/weights.json`.
- Bundle. `BUNDLE_DIR` (fresh: only `workspace.lock`, taken exclusively) receives `inputs.json` (`rusteda.native-eco-inputs.v1`: every input of the round as a file record), `roots.json` (clock and reset roots; chosen by `reset` from the nets with the most clock and reset sinks, at least 1000 each, and bound by later rounds) and `policy.json` (`rusteda.native-eco-policy.v1`), then `HEAD` (`rev1`).
- Stage. `ECO_DIR` (fresh, locked) receives `plan.json` (`rustroad.eco-plan.v1`), `netlist.v` written by the pinned `rustroad apply-eco` (its command line, standard output and standard error are kept as `apply-native-command.json`, `apply-native.stdout`, `apply-native.stderr`), for `electrical` and `hold` the next placement's `seed.json` (`rustroad.placement-seed.v1`) and `weights.json` (`rustroad.net-weights.v1`), `receipt.json` (`rusteda.native-eco-receipt.v1`) and `HEAD` (`rev1`); files appear in `ECO_DIR` only once all are written. Every file record is hashed before it is used; each timing report must be a complete `rusteda.v1` envelope of one STA revision whose compiled netlist, constraints, pin libraries and parasitics are the current files (XXH3-64 by the pinned `xxhsum`, SHA-256 of the raw Liberty copies); and every input is read in full and hashed again around the apply step: a file with settled, exact status (local file system, status changed at least a second before) while `apply-eco` runs, with its identity compared afterwards, every other file after it (`STALE_INPUT` on any difference). The receipt equals the reference's in every field but `elapsed_seconds`, `peak_rss_kib` and `planner_sha256` (the SHA-256 of this executable).
- `--plan-only` is the reference planner's `--plan-only`: no `apply-eco`, no `netlist.v`, status `planned_unverified`.
- Output. Standard output is the reference's one-line JSON summary (`schema`, `rev`, `status`, `scope`, `operations`, `plan_sha256`, `netlist_sha256`, `elapsed_seconds`, `peak_rss_kib`), not a `rusteda.v1` envelope, whatever `--format` says. A failure writes one JSON object on standard error and exits 2: `{"status": "failed", "code": ..., "error": ...}` from the bundle, `{"status": "error", "code": ..., "message": ...}` from the stage (the reference's two forms; `code` is added to the first). Codes: `USAGE`, `INPUT`, `IO`, `REVISION_CONFLICT`, `WORKSPACE_LOCKED`, `SCHEMA`, `BUDGET`, `STALE_INPUT`, `STALE_REPORT`, `REPORT`, `REPORT_SCOPE`, `REPORT_PROVENANCE`, `REPORT_TRUNCATED`, `PIN_TABLE`, `NETLIST`, `SDC_IO_UNSUPPORTED`, `SDC_IO_MISMATCH`, `POLICY`, `HANDLE`, `CAPACITY`, `PLACEMENT`, `LIBERTY`, `HOLD_INFEASIBLE`, `NATIVE_CLI`, `HASH_TOOL`, `UNSUPPORTED_VECTOR_SINK`, `UNSUPPORTED`, `TIMEOUT` (180 s for the bundle, then 180 s for the stage).
- Limits. Text inputs must be ASCII; pin tables must not quote fields. Two variants stay with the reference planner and fail with `UNSUPPORTED`: the `hold` round with `selection.electrical.cap_feedback`, and the ideal-wire and extracted-RC hold that the frontend does not run. `--threads` is accepted and unused: the command hashes on the CPUs it may use, at most four. With `RUSTEDA_FLOW_TRACE` set, the command writes the time of each phase on standard error.

**RCLI-REQ-0028** Four commands are the other helpers of the same frontend, each the native form of one command of `native_frontend_inputs.py`, writing its files byte for byte into a fresh directory `-w <DIR>` (only `workspace.lock`, taken exclusively; `--base-rev empty`) and `HEAD` (`rev1`) last; all take `--context <JSON>` as in RCLI-REQ-0027, print nothing on standard output, and fail with `{"status": "failed", "code": ..., "error": ...}` on standard error and exit code 2 (`INPUT`, `IO`, `REVISION_CONFLICT`, `WORKSPACE_LOCKED`, `LIBERTY`, `TIMEOUT` after 180 s). Text inputs must be ASCII; LEF statements are read one per line, as LEF writers emit them.

- `rusteda frontend-profiles` (`profiles`): from the two standard-cell corner libraries, the standard-cell LEF and the SDC named by the context, `cell-policy.json`, `delay.json` (`rustroad.delay-cells.v1`: every selected buffer and delay cell proven a positive-unate identity in both corners, with its delay and output transition at 0.2 ns input transition and 0.01 pF load, and the port diode), `sizing.json` (`rustroad.sizing-profile.v1`: the buffer family ordered by maximum capacitance, with drive data at 0.005 and 0.05 pF), `cell-buses.json`, `io.json` (the literal driving cells and loads of the SDC), `cts.sdc` (the clock projection for clock-tree synthesis) and `receipt.json`. `generator` in `delay.json` and `sizing.json` names the pinned reference helper (`files.prepare`), whose bytes the command writes.
- `rusteda frontend-physical --roots <JSON>` (`physical`): `physical.json` (the physical policy with `clock.root_net` set to the clock root of `--roots`), `routing.json` (the routing policy with its failure-capture path materialized inside the run) and `receipt.json`.
- `rusteda frontend-pins --def <DEF>` (`pins`): from the placed DEF of the pin-planning placement, `physical.json` with an `io_plan` (each signal pin on the nearest core side of the centroid of its loads, strongest preference first, with the centroid as its target along the side; port diodes excluded) and `receipt.json`.
- `rusteda frontend-validate` (`validate`): requires one clock tree per placement round, the pin plan, the same-run seed, the five ECO receipts and a closed final estimated-RC DRV, and writes `result.json` (`rusteda.native-frontend-result.v1`) and `digest-check.json`, the final check of the flow digest cache: every entry hashed again in full, failing on any difference.

**RCLI-REQ-0023** `rusteda show` reports the design-rule counts of a timing table as recorded when
its summary states `drv_status`; a timing summary without `drv_status` comes from an analysis that
did not check design rules, so `show` reports `drv_status: "unchecked"` and its
`max_trans_violating` and `max_cap_violating` as `null`, never as zero.
